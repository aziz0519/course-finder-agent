# M6 — AWS CDK v2 infrastructure (synth-only)

M6 P0 defines and validates the AWS target architecture locally. This milestone does
**not** bootstrap or contact an AWS account and does not prove deployment/runtime
behavior. `cdk bootstrap`, `cdk deploy`, `cdk destroy`, account-backed `cdk diff`, AWS
CLI calls, and resource provisioning are outside the current execution boundary.

## Architecture defined

One environment-specific `CourseFinderStack` keeps the initial deployment reviewable.
It defines:

- VPC across two Availability Zones with public ALB, private-with-egress application,
  and isolated database subnets. Dev uses one NAT Gateway; prod uses one per AZ. An S3
  gateway endpoint avoids routing S3 access through NAT.
- Internet-facing ALB with HTTP-to-HTTPS redirect, HTTPS listener, path routing to the
  API, and default routing to the Gradio frontend. The ACM certificate ARN is a
  CloudFormation parameter; CDK does not look up or create certificates.
- Private Fargate frontend and API services and an on-demand ingestion task definition
  (no worker service). Service discovery allows the frontend task to call the API over
  the private VPC network.
- Three ECR repositories with image scanning and immutable tags. `ImmutableImageTag`
  is a CloudFormation parameter, defaulted only to `m6-synth-placeholder` for synthesis.
  A real deployment must publish the same immutable tag to all repositories first.
- RDS PostgreSQL in isolated subnets, encrypted storage, generated Secrets Manager
  credentials, backups, CloudWatch database log export, and prod deletion protection.
  The application migration must enable PostgreSQL's `vector` extension; CDK does not
  attempt a database connection.
- Private, versioned S3 storage with KMS encryption, public-access blocks, SSL-only
  access, and noncurrent-version lifecycle retention. Dev may delete its bucket and
  versions; prod retains it.
- Cognito User Pool, public application client, and `student`, `adviser`, and `admin`
  groups. Self-sign-up is disabled. Application authorization must still verify
  student/adviser scope; group membership alone is not resource authorization.
- Separate frontend, API, ingestion-task, and task-execution roles. The frontend task
  role has no AWS data permissions; API and worker data grants are limited to declared
  S3 prefixes and their required Secrets Manager secrets.
- Encrypted CloudWatch log groups and alarms for frontend/API CPU, ALB 5xx, and RDS CPU
  and free storage.

The stack applies application, environment, owner, and data-classification tags. Dev
retention/deletion settings are intentionally disposable; prod retains data resources,
enables multi-AZ RDS and deletion protection, and lengthens backups/log/artifact
retention. Production cost, availability, and deletion settings require review before
any deployment.

## Configuration

| Variable | Meaning |
|---|---|
| `CDK_ENV` | `dev` (default) or `prod` |
| `CDK_DEFAULT_ACCOUNT`, `CDK_DEFAULT_REGION` | Optional together for dev synthesis; required together for prod synthesis. Values are consumed as strings; no account lookup is performed. |
| `RESOURCE_OWNER` | Resource owner tag (defaults to `course-finder-agent`). |
| `AcmCertificateArn` | Required CloudFormation parameter for a certificate in the deployment Region. |
| `CDK_IMAGE_TAG` | Non-`latest` immutable tag used for frontend/API/worker images; all three repositories must contain it before a deployment. |

No account identifiers, credentials, or secrets are committed. RDS and session secrets
are generated by Secrets Manager at deployment time and are never CDK outputs.

## Local setup and validation

Install the project's groups and synthesize locally:

```bash
uv sync --all-groups
uv run python -m infra.app
```

This emits the CloudFormation cloud assembly to `cdk.out/` without AWS API calls. If
the AWS CDK CLI is installed locally, `cdk synth` uses `cdk.json` to invoke the same app.
Do not run AWS-backed commands under the current M6 boundary.

Run CDK assertion tests, infra lint/type checks, and the ordinary suite:

```bash
uv run pytest infra/tests -q
uv run ruff check infra/
uv run mypy infra
uv run pytest
```

The assertion tests inspect synthesized CloudFormation for resource counts, network
placement, ALB listeners, private/encrypted RDS and S3, Cognito groups, immutable ECR
repositories, and environment-specific retention/deletion controls. They prove template
properties only—not AWS service support in a particular account/Region or deployed
connectivity.

## Known runtime work not proven by P0

- Build/publish compatible images to all three repositories before deploying ECS
  services. The placeholder tag is for synth only.
- The current local app uses local auth and local SQLite/filesystem adapters. Production
  Cognito verification, RDS configuration/migrations, S3 storage adapters, and ingestion
  task invocation still require application/runtime integration.
- Confirm ACM certificate/domain, account and Region, model-provider egress, cost, and
  operational ownership before deployment.
- Review synthesized templates and `cdk diff` only in an authorized future deployment
  phase. No live deployment validation is included in M6 P0.
